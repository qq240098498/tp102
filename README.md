# tp102 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5102>

端口固定为 `5102`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
3. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条，并按级别、按规则、按文件分别汇总
4. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 多人同时改同一条规则

- 点编辑之前先在右上角填上当前操作者的名字。打开编辑表单时这条规则就被占住，规则列表的占用列会写明当前被谁占着、从什么时候开始
- 同一个人重复打开同一条规则不算冲突；换个人打开会弹出提示，说明占用人与开始时间，由操作者决定等对方改完，还是把当前内容另存为一条新规则（另存时需要填一个不重复的编码）
- 保存时服务端会比对打开那一刻的内容：占用期间这条规则被别处改动过的话，本次保存会被当场拦下，列出是哪几项被改了、打开时是什么、现在是什么，由操作者选择覆盖保存或者放弃本次改动
- 选择覆盖保存会留下痕迹：点规则行的记录可以看到这条规则的新建、修改与覆盖历史，覆盖记录里写清了这次覆盖掉的是谁在什么时候的哪些改动
- 取消编辑、保存成功、删除规则或关掉页面都会释放占用；规则被删除后它的占用自动失效，修改记录仍然保留

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...], "locks": [...], "ruleHistory": [...] }`。`locks` 是规则的编辑占用（占用人、开始时间与打开那一刻的内容快照），`ruleHistory` 是规则的新建、修改与覆盖痕迹（最多保留最近 500 条）。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索，返回里带当前占用列表 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则；占用者保存时若内容被别处改过会返回冲突差异，带 `force: true` 则覆盖保存并留下痕迹 |
| DELETE | /api/rules/:id    | 删除规则                                         |
| POST   | /api/rules/:id/lock   | 打开编辑表单时占住这条规则；被别人占着时返回占用人与开始时间 |
| POST   | /api/rules/:id/unlock | 释放这条规则的占用（只有占用者本人能释放）       |
| GET    | /api/rules/:id/history | 这条规则的新建、修改与覆盖痕迹，新的在前        |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按启用的规则扫一遍，返回命中清单与汇总           |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上；占用与保存冲突的错误会额外带一个 `details`，里面是占用人与开始时间，或者逐项列出的差异（哪几项被改了、打开时是什么、现在是什么）。
