# tp102 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5102>

端口固定为 `5102`，如需临时改动可在启动前设置环境变量 `PORT`。占用锁默认 90 秒没有心跳就自动收回，可用环境变量 `LOCK_TTL_MS` 临时调整（排查并发场景时用）。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除，每条规则多一个“改动记录”入口
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
3. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条，并按级别、按规则、按文件分别汇总
4. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

编辑规则前先在页面右上角填上当前操作者（会记在本机），然后：

- **打开即占用**：点编辑会先占住这一条规则，表单顶部写明你从什么时候开始占用、占用的是第几版；规则清单的“占用”列也会标出谁正占着、从什么时候开始（自己占用显示绿色）。占用期间页面每 25 秒自动报一次心跳，取消、保存或关掉标签页都会放开；超过 90 秒没有心跳会自动收回
- **同一个人重复打开不算冲突**：同一操作者在多个标签页打开同一条规则都能直接进表单，互不影响
- **换个人打开会提示**：弹窗写清占用人与起始占用时间，由操作者选择“等待对方释放”（每隔几秒自动看一眼，对方一放开就接上编辑）或“另存为新规则”（带着当前内容进入新建表单，改个编码保存成独立的一条，不动对方占用的那一条）
- **保存时比对打开时的内容**：每次保存都带着打开时的版本号；占用期间这一条被别处改过，保存会当场拦下，弹窗逐项列出哪几项被改了、打开时是什么、现在是什么、你这次填的是什么，并列出占用期间落了哪几版、各是谁改的。操作者可以选“覆盖”（用自己的内容保存）或“放弃本次改动”
- **覆盖留痕**：选择覆盖后会生成一条“覆盖”类型的改动记录，明确写出这次盖掉的是第几版、谁、什么时候的改动；规则的新建、普通改动、覆盖都可以在“改动记录”里从第一版逐条查看
- 别人正占用的规则不能删除，等对方保存或取消后再删

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

每条规则除了业务字段还带 `version`（当前版本号，从 1 开始）与 `history`（改动记录，最多保留 50 条）。改动记录分三种类型：`create`（建档/初始基线）、`edit`（普通改动）、`overwrite`（覆盖保存，`overwrote` 字段写明盖掉了哪几版、各是谁在什么时候改的），每条记录的 `changes` 逐项写出字段的旧值与新值。旧数据文件没有这两个字段时，载入会自动补上第 1 版建档基线，不影响原有数据。

编辑占用锁只存在服务进程内存里（`server/locks.js`），不写进数据文件，服务重启后所有占用清空；这符合单机本地工具的用法，也避免把临时占用状态落盘。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单（每条带 version 与当前占用），支持筛选与搜索 |
| POST   | /api/rules        | 新建规则（body 里带 operator）                   |
| GET    | /api/rules/:id    | 查看单条规则（含改动记录与占用）                 |
| POST   | /api/rules/:id/edit-lock | 打开编辑：同人新标签页直接通过，异人占用返回 409 RULE_LOCKED，detail 里给占用人与起始时间 |
| POST   | /api/rules/:id/edit-lock/heartbeat | 占用心跳续期，失效返回 409 RULE_LOCK_LOST |
| DELETE | /api/rules/:id/edit-lock | 释放本标签页的占用（另有 POST …/release 供关闭页面时 sendBeacon 用） |
| PATCH  | /api/rules/:id    | 修改规则，必须带 operator、clientId、expectedVersion；占用期间内容被改过返回 409 RULE_CONTENT_CHANGED（detail 逐项给打开时/现在/本次填的值与中间版本）；带 force=true 表示确认覆盖 |
| GET    | /api/rules/:id/history | 一条规则的全部改动记录                       |
| GET    | /api/rule-locks   | 当前全部占用快照                                 |
| DELETE | /api/rules/:id    | 删除规则；别人正占用时返回 409 RULE_LOCKED       |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按启用的规则扫一遍，返回命中清单与汇总           |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "...", "detail": ... } }`，其中 `field` 用于让页面把问题标到具体的输入项上，`detail` 承载占用信息或保存冲突时的逐项对比。
